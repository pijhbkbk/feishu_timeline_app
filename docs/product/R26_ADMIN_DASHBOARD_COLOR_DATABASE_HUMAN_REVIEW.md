# R26 系统管理与颜色数据库人工验收

## 系统管理首页

1. 打开 `/admin`。
2. 确认第一屏只有 6 项数据：项目总数、进行中项目、风险项目、启用人员、启用部门、已归档颜色。
3. 确认首页只有“进入管理”和“颜色数据库”两个大入口。
4. 点击“刷新数据”，确认数据更新时间更新且没有长期加载。
5. 在 1440、1024 和 390 宽度确认指标分别为 6 列、3×2、2 列排列。

## 进入管理

1. 点击“进入管理”。
2. 确认进入 `/admin/manage`。
3. 依次打开项目与工序、组织与成员、分工与权限、流程与参数、审计与异常中的既有页面。
4. 确认原管理能力没有被删除，系统概况首页也没有重复平铺这些入口。

## 颜色数据库

1. 点击“颜色数据库”，进入 `/admin/color-database`。
2. 搜索颜色名称、颜色编号、车型和项目编号。
3. 依次使用车型、颜色类别、状态、材料完整度和年份筛选。
4. 打开一个颜色档案，确认可看到颜色基本信息、关联项目和七个生命周期材料阶段。
5. 抽查材料的文件名、工序、版本、提交人、部门、来源项目、提交时间和当前/历史版本标识。
6. 点击“查看”或“下载”，确认使用原附件系统读取文件。

## 安全边界

- 页面不提供第二套材料上传入口。
- 页面不允许删除原始附件或审计记录。
- 普通成员只能读取本人负责、参与或所属部门有权访问项目的颜色资料；不能读取越权颜色详情。
- 本轮验收地址应为独立 staging；不要将 production 页面作为本轮通过证据。

## 待产品负责人确认

- 首页信息密度和两个入口的视觉主次是否合适。
- 颜色档案的七阶段分类是否符合日常检索习惯。
- 第一版是否维持只读归档，暂不开放合并、拆分和分类修正。
