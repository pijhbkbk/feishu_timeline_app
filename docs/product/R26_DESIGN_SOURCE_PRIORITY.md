## 3. 不可变优先级

### P1：Apple 风产品 UI

决定：

- 全局信息架构；
- 五项主导航；
- 页面标题、正文、辅助文本的字号层级；
- 页面最大宽度、栅格、留白、卡片比例；
- 中性色、品牌色和状态色；
- 工作台、项目管理、项目工作区、进展提交、任务、材料、复盘、后台的正式页面形态；
- 桌面、平板、手机三种响应式框架。

P1 的冲突裁决权高于 P2 和 P3。P2/P3 不得新增一套全局导航、字体系统或页面外壳。

### P2：项目实时流程地图

只在以下范围具有决定权：

- 项目工作区中的固定流程拓扑；
- 18 个节点的形状、状态和连线语义；
- 节点 hover、点击、选中、URL 恢复；
- 工序详情抽屉；
- 第 12、17、18 步的特殊形态；
- 地图、抽屉、活动流的刷新节奏；
- 桌面抽屉与移动端全屏工序面板。

P2 不得把 `/projects/:id/flow-map` 发展为第二个主项目产品，也不得覆盖 P1 的五项主导航。R26 V2 以 `/v2/projects/:projectId` 为项目工作区唯一主入口，`taskId` 作为节点选中状态。

### P3：系统导览

只决定 `/v2/guide` 页面内部：

- 导览首页；
- 18 步分组说明；
- 业务规则卡片；
- 操作路径；
- 角色说明；
- 材料矩阵；
- FAQ 与快捷入口。

P3 中的旧侧边栏、八项主导航、数据中心入口命名，不得覆盖 P1 的全局信息架构，也不得覆盖 P2 的项目工作区。

## 4. 三份设计源的冲突裁决

| 冲突 | P1 | P2 / P3 提议 | R26 固定决定 |
|---|---|---|---|
| 全局导航 | 工作台、项目管理、我的任务、进展提交、复盘分析 | P3 提议导览侧边栏和更多业务入口 | 使用 P1 五项主导航；帮助图标进入 `/v2/guide` |
| 项目主入口 | 两栏项目工作区：流程 + 当前工序 | P2 单列 `/projects/:id/flow-map` | `/v2/projects/:projectId` 是唯一主入口；地图是页面主画布 |
| 项目内导航 | 轻量项目上下文 | 当前实现有 7 个横向标签，P2 还有左侧项目切换 | 桌面只保留项目切换、概览、材料/记录等次级入口；不形成第二套主导航 |
| 字体 | Apple 系统字体栈、PingFang SC 优先 | P2/P3 使用 Noto Sans CJK SC | 全局使用 P1 字体；Noto 只作为系统 fallback |
| 容器语言 | 轻、平、低阴影、稳定留白 | P2/P3 有大胶囊和 48px 级圆角 | 保留 P1 容器语言；只移植 P2 的节点语义 |
| 开发收费 | 页面展示业务事实 | P2 文案写死 10000 元 | 金额必须来自后端流程定义/系统参数，前端不得硬编码 |
| 进展提交 | 三步：做了什么、是否阻塞、上传材料 | P3 只做操作说明 | 正式交互由 P1 决定，P3 只解释 |
| 帮助页 | 顶部帮助入口 | P3 独立侧边栏 | 使用 P1 App Shell；P3 导览只在页面内部锚点导航 |

## 8. PPT 注释与网页内容边界

以下内容仅是设计稿说明，不得原样进入产品页面：

- `PAGE DESIGN`
- `DESIGN SYSTEM`
- `INFORMATION ARCHITECTURE`
- 页码、标尺、设计解释、实施批次说明
- `DEMO`、`ACTIVE` 等演示或内部状态标签
- `Required`、`Upload`、`History`、`Executive summary`、`Stage comparison`、`Learning`、`Audit` 等未本地化的设计标注

网页需要还原的是信息层级、留白、卡片比例、状态语义和交互逻辑，而不是复制 PPT 的说明性文字。
