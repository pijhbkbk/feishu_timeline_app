# R26_PRODUCT_UI_RECOVERY — UI 验收标准

## 1. 总原则

R26 UI 完成证据必须来自用户可见结果。

以下项目不能单独证明 UI 完成：

- lint 通过；
- typecheck 通过；
- build 通过；
- test 通过；
- API 返回 200；
- 路由存在；
- 容器 healthy；
- systemd active；
- VPS 已 pull；
- `/api/health` 返回 200。

它们仍是工程门禁，但不能替代正式域名截图、交互路径和视觉对比。

## 2. 轮次门禁

### Gate 0：设计与现状

必须：

- 三份 PPT 均逐页解析；
- 设计源优先级冻结；
- 当前线上正式路由截图完成；
- 路由与组件树完成；
- 逐页差异矩阵完成；
- 旧 UI 废弃清单完成；
- V2 路由和 Feature Flag 隔离方案完成；
- V2 页面结构完成；
- 项目工作区数据模型完成；
- 固定 SVG 拓扑完成；
- 三条角色路径完成；
- Gate 1 静态原型计划完成。

Gate 0 不允许修改产品代码。

### Gate 1：静态原型

必须：

- V2 独立路由，不替换 V1；
- 所有正式 V2 页面使用静态 typed fixtures 完整呈现；
- 重点页面为工作台、项目工作区、进展提交；
- 三视口截图完成；
- PPT 与 Web 并排对比完成；
- 每页评分达到 90；
- 视觉闸门确认后停止。

Gate 1 不接真实写 API，不部署。

### Gate 2：真实数据与交互

必须：

- 只读和写操作使用真实 API；
- 流程动作仍由后端判定；
- 无长期骨架屏或整页空白；
- 状态、加载、空态、错误、权限态可见；
- 三条角色路径通过；
- 响应式和无障碍通过；
- 安全修复无回退。

### Gate 3：预发布

必须：

- 预发布地址；
- 所有正式页面截图；
- PPT 并排对比；
- 每页评分；
- Playwright 交互证据；
- 安全、权限、数据非回归报告；
- Git diff 与 exact commit；
- 未解决视觉偏差。

得到发布闸门确认前不得部署生产。

### Gate 4：生产

必须：

- 先备份生产数据库；
- exact commit、分支、构建 provenance、VPS HEAD 一致；
- 生产域名下每个正式页面真实截图；
- 生产域名下三条角色路径；
- 回滚门禁与观察结果；
- 不出现 seed、PPT 背景或内部演示文案。

## 3. 视觉评分

每页 100 分：

| 维度 | 分值 | 失败示例 |
|---|---:|---|
| 信息结构 | 25 | 主问题不清楚、多个同级主动作、技术模块堆叠 |
| 字体层级 | 20 | 主要业务事实使用 12–13px、标题层级混乱 |
| 留白与对齐 | 20 | 卡片拥挤、边距不一致、内容为了塞入而缩小 |
| 颜色与状态 | 15 | 只靠颜色、状态语义缺失、低对比 |
| 交互与主动作 | 10 | 找不到下一步、点击无反馈、抽屉不能恢复 |
| 响应式与可读性 | 10 | 390px 溢出、触控目标太小、底部按钮遮挡 |

通过线：

- 每页总分 ≥ 90；
- 任一维度不得低于该维度满分的 80%；
- 重点页面不能通过平均分掩盖单页失败；
- 骨架屏持续、整页空白、权限泄漏、写操作越权均直接判 `FAIL`。

## 4. 全局视觉标准

### 4.1 字体

字体栈：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text",
"PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif
```

字号：

- 页面主标题：36–40px；
- 区块标题：28px；
- 卡片标题：18px；
- 正文：16px；
- 辅助信息：14px；
- 12–13px 只允许时间戳、步骤号、非关键 overline；
- 任何需要用户决策的业务事实不得只用 12–13px。

### 4.2 布局

- 最大内容宽度：1440px；
- 8px 间距体系；
- 桌面左右边距至少 32px；
- 1024px 左右边距至少 24px；
- 390px 左右边距 20px；
- 卡片默认内边距 24–32px；
- 圆角 14–20px，避免整页大胶囊；
- 阴影轻且仅用于层级，不用于装饰。

### 4.3 状态

必须同时使用颜色和文字/图标：

- 已完成；
- 进行中；
- 待评审；
- 逾期；
- 退回；
- 月度评审；
- 颜色退出；
- 阻塞；
- 缺材料。

### 4.4 文案

正式页面不得出现：

- `DEMO`
- `ACTIVE`
- `DEMO - ACTIVE`
- `Required`
- `Upload`
- `History`
- `Executive summary`
- `Stage comparison`
- `Learning`
- `Audit`
- 开发轮次、组件名、测试 ID、PPT 注释

允许保留业务约定的英文缩写时，必须有明确中文语义，例如 SLA。

## 5. 响应式标准

### 1440 × 900

- 使用完整桌面信息架构；
- 项目工作区可展示项目切换、地图、抽屉三栏；
- 首屏能看到当前节点和主动作；
- 不用缩小字体塞入内容。

### 1024 × 768

- 主导航仍可读；
- 项目工作区改为地图 + 覆盖式抽屉，或地图上方摘要；
- 次级导航可横向滚动但不截断；
- 卡片顺序保持。

### 390 × 844

- 五项主导航可使用底部导航；
- 页面无横向溢出；
- 正文仍为 16px；
- 项目地图允许受控缩放/平移；
- 工序详情是全屏 sheet；
- 固定底部主动作不遮挡内容；
- 触控目标至少 44 × 44；
- 键盘弹出后表单仍可提交。

## 6. 页面验收

### `/v2/dashboard`

- 大字号问候；
- 一张明确的当前任务卡；
- 一个主按钮；
- 下一任务、四项 KPI、最近动态层级低于当前任务；
- 无任务、加载失败、权限失败可见；
- 30 秒刷新不闪回整页骨架。

### `/v2/projects`

- 项目卡直接显示停滞原因；
- 显示当前工序、负责人、截止、进度、更新时间；
- 快速筛选清晰；
- 高级筛选折叠；
- 无假项目、假金额或硬编码进度。

### `/v2/projects/:projectId`

- 使用固定 SVG 拓扑；
- 第 12、17、18 步形状正确；
- 当前、逾期、退回、阻塞可同时区分；
- 点击节点打开抽屉；
- `?taskId=` 刷新后恢复；
- 抽屉字段完整；
- 当前任务主动作可到进展提交；
- 不存在第二套时间线/流程地图导航；
- 可见层不得长期停留骨架屏。

### `/v2/progress`

- 明确三步；
- 项目/工序上下文自动带入；
- 有阻塞时字段强制出现；
- 材料清单来自任务；
- 保存草稿与提交区分；
- URL 改写不导致空白；
- 提交后有项目历史证据；
- 防重复提交。

### `/v2/tasks`

- 五种队列在同页切换；
- 每个任务只有一个状态匹配的主动作；
- 逾期、评审、缺材料优先级清晰；
- 不再出现 `/todos` 等竞争入口。

### `/v2/materials/upload`

- 必交、已上传、添加材料三部分；
- 版本和替换关系可见；
- 不放宽扩展名、MIME、魔数、路径、权限校验；
- 错误提示明确；
- 不出现内部英文标注。

### `/v2/projects/:projectId/retrospective`

- 先给结论；
- 计划与实际可比较；
- 最慢阶段、瓶颈、延期原因清楚；
- 改进项有负责人和截止；
- 已完成复盘不可静默覆盖历史。

### `/v2/admin`

- 只显示组织、权限、流程参数、审计四类；
- 普通用户不可见；
- 服务端权限拒绝有清楚状态；
- 审计列表有界、可筛选、可打开详情；
- 不使用占位页面冒充完成。

### `/v2/guide`

- 不覆盖全局导航；
- 18 步、规则、操作、角色、材料、FAQ 可快速定位；
- 链接全部进入 V2；
- 不硬编码可能由后端参数决定的金额；
- 390px 可读。

## 7. 操作路径标准

### 员工

- 5 秒内找到当前任务；
- 60 秒内完成一条进展；
- 进展、阻塞、材料均落到真实后端；
- 提交后项目历史可见。

### 项目经理

- 5 秒内定位风险项目；
- 2 次点击内打开风险节点；
- 同一抽屉看到负责人、阻塞、SLA、材料、历史；
- 未授权动作不显示且服务端拒绝。

### 管理层

- 从项目组合到项目地图再到复盘路径连续；
- 不需要进入多个技术模块拼接结论；
- 管理员审计有列表和详情；
- 普通管理层与系统管理员能力不混淆。

## 8. 加载与可靠性

- 首屏骨架目标 < 1 秒，超过 3 秒必须出现明确解释和重试；
- 不允许无限 skeleton；
- 不允许 URL 已变化但页面仍显示上一页；
- 不允许页面 DOM 有内容但可见层仍为骨架；
- 不允许整页空白；
- 轮询失败保留上次成功数据；
- 表单编辑期间不覆盖用户输入；
- 每页必须覆盖 loading / empty / error / permission / success。

## 9. 数据与安全非回归

必须保留：

- OAuth state 校验；
- session 安全与登出失效；
- Origin / same-origin 校验；
- 后端角色、权限、项目范围、任务负责人和指定评审人边界；
- 流程状态和评审门禁；
- 幂等写操作；
- 审计日志；
- 对象存储附件和数据库元数据分离；
- 扩展名、MIME、文件魔数、大小、路径穿越校验；
- 依赖和镜像安全修复。

生产禁止：

- seed 项目；
- 演示人员；
- 硬编码收费；
- 硬编码进度或流程状态；
- PPT 截图背景；
- 内部测试标签；
- 假成功提示。

## 10. 必须提交的证据

每个正式页面：

- PPT 参考页；
- 1440、1024、390 Web 截图；
- 并排对比；
- 六维评分；
- 加载/空态/错误/权限至少一种补充截图；
- 交互录像或 Playwright 步骤记录；
- 未解决偏差。

发布阶段还必须：

- 预发布和生产域名；
- exact commit 与构建来源；
- 数据库备份与回滚点；
- 三条角色路径；
- 生产截图；
- 无 `DEMO - ACTIVE` 和同类异常文案的文本扫描结果。
