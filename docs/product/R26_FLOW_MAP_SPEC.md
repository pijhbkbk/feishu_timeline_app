# R26_PRODUCT_UI_RECOVERY — 实时流程地图规范

## 1. 目标

项目经理在 5 秒内回答：

1. 项目现在在哪一步；
2. 哪些节点已经完成；
3. 哪些节点逾期、退回、阻塞或缺材料；
4. 当前谁负责；
5. 下一步是什么。

地图只存在于 `/v2/projects/:projectId` 主工作区。不得再建立竞争性的时间线或流程地图主入口。

固定拓扑的补充视觉证据：

- [流程固定拓扑原图](evidence/r26/design-sources/flow-map-topology-reference.png)
- SHA-256：`6cf979613e2d08d8eaac41b04cc348a1597c26bf10853492a0945a264dcba4fc`

该图确认：

- 第 4 步同时进入第 5 步取号和第 6 步采购；
- 第 6 步同时进入第 9 步性能试验、第 7–8 步标准板支线和第 10 步首台计划；
- 第 12 步 `N` 返回第 11 步；
- 第 12 步 `Y` 同时进入第 13 步收费支线和第 14 步一致性评审主线；
- 第 14–18 步继续构成主链路。

## 2. SVG 画布

固定定义：

```text
viewBox = "0 0 1440 1740"
preserveAspectRatio = "xMidYMin meet"
desktop node gap = 18–38
minimum interactive target = 44 × 44
```

布局坐标是流程语义的一部分。状态变化只能改变节点/连线样式，不得改变节点位置。

## 5. 节点状态

| 状态 | 颜色 | 节点处理 | 连线处理 |
|---|---|---|---|
| `NOT_STARTED` | 灰 | 低对比填充 | 灰 |
| `PENDING` | 中性蓝灰 | 有任务、未开始 | 灰/蓝灰 |
| `IN_PROGRESS` | 品牌蓝 | 蓝色描边与轻填充 | 蓝 |
| `PENDING_REVIEW` | 橙 | 评审标识 | 橙 |
| `COMPLETED` | 绿 | 绿色完成标识 | 绿 |
| `COMPLETED_LATE` | 绿 + 红角标 | 完成但保留迟延事实 | 绿 |
| `OVERDUE` | 红 | 红色描边、逾期天数 | 红 |
| `RETURNED` | 紫 | 退回标识、轮次 | 紫色返回线 |

颜色必须满足正文/背景 WCAG AA。不能只依靠颜色，节点同时显示图标、状态词或数值。

## 6. 节点内容

默认节点：

```text
步骤号 + 状态图标
工序名称
负责人或责任部门
截止日期 / 逾期天数
```

紧凑层级：

- 工序名称 16px / 600；
- 负责人、部门、日期 14px；
- 步骤号和状态辅助可使用 12–13px，但不得承载唯一业务事实。

节点 tooltip：

- 状态；
- 负责人；
- 截止时间；
- 材料进度；
- 阻塞摘要。

## 7. 点击与 URL

点击节点：

1. 设置选中描边；
2. 打开右侧工序抽屉；
3. 如果节点有 taskId，写入 `?taskId=:taskId`；
4. 如果尚未生成任务，只写入 `?nodeCode=:nodeCode`；
5. 不滚动页面顶部，不重置地图位置。

恢复：

- 刷新页面后按 `taskId` 恢复；
- 无效/无权限 taskId 由 API 返回受控错误，页面不崩溃；
- 关闭抽屉时移除 `taskId/nodeCode`，保留其它 query；
- 复制页面链接可恢复同一节点。

## 8. 工序详情抽屉

字段顺序：

1. 工序名称、步骤、状态、轮次；
2. 负责人、协作人、审批人、责任部门；
3. 开始、截止、剩余工作日、逾期天数；
4. 工作要求与输出物；
5. 必交材料、已上传附件、缺失项；
6. 评审、费用、月度评审或颜色退出特殊区；
7. 最近流转与审计记录；
8. 当前用户可执行动作。

动作必须使用 API 返回的 `availableActions`。前端不得根据角色字符串或节点状态自行拼接。

移动端：

- 抽屉改为全屏 sheet；
- 顶部固定关闭、工序名、状态；
- 底部固定主动作；
- 内容区独立滚动；
- 390px 宽度下不横向溢出。

## 9. 特殊节点

### 第 12 步：样车驾驶室评审

- 菱形节点；
- 抽屉必须显示通过/驳回；
- 驳回必须填写原因和返工要求；
- 退回第 11 步时生成新轮次；
- 历史轮次只读、不可覆盖。

### 第 17 步：整车色差一致性评审

- 环形进度；
- 固定拓扑图可使用短名“色差目视评审”，详情抽屉和正式页面使用完整业务名称；
- 显示 `x / 12`；
- 明确本月、已逾期月份和下一评审日期；
- 点击进入当前月度实例，不把 12 个月压成单一布尔状态。

### 第 18 步：颜色退出

- 终点节点；
- 显示年产量、阈值、系统建议、最终人工决定；
- 系统建议不能代替人工决定；
- 只有后端授权用户能完成。

## 10. 实时更新

Gate 2 初始策略：

- 地图：30 秒；
- 当前抽屉：15 秒；
- 组合统计/活动：60 秒；
- 用户可手动刷新；
- 编辑表单时暂停把远端响应覆盖到输入值；
- 写操作成功后主动刷新地图和抽屉；
- 失败时保留上一次成功结果，并显示非阻塞提示。

后续可评估 SSE/WebSocket，但不是 Gate 1 或 MVP 必需条件。

## 11. 数据契约

地图使用现有：

- `ProjectFlowMapResponse`
- `ProjectFlowMapNode`
- `ProjectFlowMapEdge`
- `ProjectFlowMapActivity`
- `WorkflowTaskInteractionDetail`

Gate 2 前必须补齐的契约审计：

- node status 是否覆盖 `EXIT_PENDING`；
- edge status 是否能区分 overdue；
- blocker 摘要是否进入地图响应；
- 负责人/责任部门缺失时的明确 fallback；
- `lastUpdatedAt` 是否代表地图完整快照；
- 费用金额是否完全来自服务端；
- taskId 无权限/已失效的受控响应。

## 12. Gate 1 静态原型验收

- 18 个节点位置与本规范逐项一致；
- 第 12、17、18 步形状正确；
- 四类连线语义可区分；
- 至少展示完成、当前、评审、逾期、退回、月度、退出七种视觉状态；
- 点击节点打开抽屉；
- query 恢复有静态演示；
- 1440、1024、390 三视口可用；
- 不出现 V1 时间线或第二个流程地图入口；
- 不接真实写 API，不部署。
