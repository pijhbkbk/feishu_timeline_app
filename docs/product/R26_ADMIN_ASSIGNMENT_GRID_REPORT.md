# R26 项目分工配置可编辑表实施报告

## 结论

`/admin/assignments` 已从只读责任矩阵升级为受控的多字段分工表。管理员可以像使用多维
表格一样，从任意带铅笔的单元格或行尾“编辑分工”进入编辑面板；正式保存仍由服务端
完成权限、版本、候选人、流程边界和幂等校验。

本轮没有把飞书多维表格设为业务主数据源，也没有申请或扩大飞书权限。系统内数据库仍
是项目、任务、流程与审计的唯一事实来源。

## 可编辑字段

| 字段 | 交互类型 | 服务端约束 |
|---|---|---|
| 主责部门 | 关联字段 | 只能选择启用部门 |
| 默认负责人 | 单选人员 | 必须是当前项目有效成员，且属于所选主责部门 |
| 协同人员 | 多选人员 | 必须是当前项目有效成员，不得与负责人或评审人重复 |
| 评审人员 | 多选人员 | 仅评审节点可配置，不得与负责人或协同人重复 |
| 生效范围 | 单选 | 未来任务、未开始任务、经确认的进行中任务三档 |
| 变更原因 | 长文本 | 必填，写入审计元数据 |

表格同时展示 18 个固定流程节点、当前/建议负责人、协同与评审关系、匹配状态和分配
来源。编辑面板中的候选人、部门和节点类型全部来自服务端，前端不按角色名或部门名
推导负责人。

## 保存协议

1. 管理员编辑字段；
2. 调用 preview 接口，只计算影响，不写业务数据；
3. 展示当前值、调整后值、阻断原因、警告和生效范围；
4. 管理员点击“确认执行变更”；
5. 服务端校验 `expectedVersion`、权限、项目成员、部门关系和
   `Idempotency-Key`；
6. 在单个 Prisma 事务中更新项目节点分工、按所选范围更新允许更新的任务、递增项目
   分工版本并写入审计日志；
7. 前端重新读取服务端 ViewModel。

该命令没有下一节点、任务状态、项目状态或流程当前节点字段，不能绕过既有状态机。
已完成历史不会被改写。

## 已验证结果

- 真实页面加载 18 个节点，fixture 命中数为 0；
- 影响预览明确显示“尚未写入任何业务数据”；
- 本地隔离项目完成一次正式保存，项目分工版本由 1 递增至 2；
- 刷新后主责部门和负责人保持；
- 第二次并发验证中，先保存页面将版本由 2 递增至 3，旧页面收到
  “项目分工已被其他管理员修改，请刷新后重试”；
- 匿名请求返回 401，普通员工请求返回 403；
- 审计日志记录
  `ADMIN_PROJECT_NODE_ASSIGNMENT_CHANGED`、操作者、项目、工序、请求编号、变更前后值和
  原因；
- 本轮保存仅作用于本机隔离数据，没有 production 请求。

## 响应式边界

- 桌面端提供完整表格和编辑面板；
- 小笔记本保留横向表格滚动与右侧编辑面板；
- 手机端使用只读分工卡片，不在窄屏提供高风险批量编辑，明确提示在桌面端完成变更；
- 编辑面板内容独立滚动，顶部结论与底部操作保持可见。

## 发布边界

本轮只能部署到独立 staging 供产品负责人验收。不得自动发布 production、合并
`main` 或创建稳定 tag。
