# R26_ADMIN_TABLE_CONTROL_CENTER

## 目标

把 R26 的后台视觉入口升级为真实、桌面优先、表格驱动的管理控制中心。所有数据来自
staging 数据库；允许的修改必须经过服务端权限、字段白名单、影响预览、乐观锁、幂等、
事务和审计，不能绕过既有工作流状态机。

## 部署边界

- 分支：`codex/r26-admin-table-control-center`
- 环境：独立 staging
- production：禁止访问与部署
- V1：不修改
- `main`：不合并
- tag：不创建
- 人工门禁：完成 staging 技术验收后停止

## 页面

- `/admin`
- `/admin/projects`
- `/admin/tasks`
- `/admin/organization`
- `/admin/assignments`
- `/admin/permissions`
- `/admin/workflow-templates`
- `/admin/dictionaries`
- `/admin/audit-logs`

## 允许的管理命令

- 项目展示信息修改；
- 工序计划日期预览与调整；
- 工序主责部门、负责人、协同人与评审人预览与调整；
- 多工序原子批量调整；
- 正式 CSV 模板 dry-run 与计划日期导入；
- 用户启用、停用与锁定；
- 非系统保留字典项维护；
- 创建只影响未来项目的新流程模板版本。

## 永久禁止的直接编辑

- 项目状态；
- 工序状态；
- 当前节点；
- 实际完成时间；
- 第 12 步评审结论；
- 第 13 步收费状态与固定金额；
- 第 17 步月度结论；
- 第 18 步人工退出结论；
- 审计记录。

## 验收

1. 九个后台页面均展示真实数据，不出现占位骨架；
2. 项目、工序、组织表使用服务端分页、筛选与排序；
3. 产品已决定删除保存视图入口；项目台账与工序台账均固定使用精简列，不提供完整列切换；
4. 批量变更和导入先 dry-run，失败时原子回滚；
5. 写请求均有原因、版本、幂等键、事务和审计；
6. 历史工序不可覆盖，冲突返回 409；
7. 1440、1024 可完整操作，390 为只读卡片；
8. console/page error 为 0，production 请求为 0。

## 2026-08-03 产品收敛补充：公司部门

- “公司部门”页签排在“系统用户”之前。
- 部门列表不展示编码列、路径编码或其他内部编码；“上级部门”对用户统一称为“所属事业部”。
- 部门新增/编辑取消前端影响预览，提交一次确认后直接调用现有服务端写命令。
- 取消前端预览不取消服务端安全门禁：版本校验、幂等键、字段白名单、权限、事务和审计继续保留。
- 本补充只改变 `/admin/organization` 的部门展示与交互，不修改组织数据、数据库结构或工作流。

## 2026-08-03 产品收敛补充：保存视图与部门删除

- 后台控制中心不再展示“保存视图”选择器和“保存当前视图”按钮，前端也不再请求保存视图接口；
  后端兼容接口和历史数据表暂不删除，避免引入无关 migration 风险。
- 公司部门表支持逐行选择、当前页全选、取消选择与批量删除；移动端提供等价选择入口。
- 删除只允许无业务引用的非根部门；根部门、有关联人员、下级部门、项目、工序、分工配置或
  标准板发放记录的部门必须返回明确冲突，不能依赖前端隐藏或禁用按钮代替服务端校验。
- 删除命令必须执行超级管理员权限、项目访问边界、乐观锁、幂等、事务与审计；同一批次任一项
  失败时全部不删除。

## 2026-08-05 产品收敛补充：项目台账精简列

- 项目台账固定保留精简列，不再提供“显示完整列”或“使用精简列”切换。
- 删除完整列模式的前端状态和渲染分支，避免隐藏入口或后续状态复用重新启用。
- 工序台账继续固定使用精简列；本补充不修改 API、数据库、权限、项目数据或工作流。

## 2026-08-05 产品收敛补充：后台表格对齐

- 所有正式后台表格的表头和正文文字必须同时水平居中、竖直居中，不能只修复单一路由。
- 公司部门表中状态与“编辑部门”操作必须保留明确间距，避免文案与按钮粘连。
- 本机真实数据浏览器复核覆盖项目台账、工序台账、组织与人员、分配配置、角色权限、
  审计与异常六个路由；其表头和单元格计算样式均为 `center / middle`。
- 本补充仅改变显示布局，不修改 API、数据库、权限、流程状态或业务数据。

## 2026-08-05 产品收敛补充：所属事业部固定清单

- 公司部门新增/编辑面板的“所属事业部”只允许选择：技术中心、商用车营销事业部、
  乘用车营销事业部、制造中心、国际事业部、采购中心。
- 六个事业部作为受控参考组织写入 migration 和 seed，不在“公司部门”业务表格中展示，
  也不能把普通公司部门伪装成事业部候选项。
- 前端候选项完全读取服务端 `businessDivisions`，不得根据部门名称或现有部门树自行拼装。
- 服务端预校验和正式事务均校验事业部编码与名称的精确组合；缺失、停用或清单外归属必须拒绝。
- 历史部门原归属不在固定清单时，编辑面板显示“请选择所属事业部”，不默认误选第一项。

## 2026-08-05 产品收敛补充：关闭按钮视觉一致性

- 管理编辑抽屉、审计详情抽屉以及项目工作区的图标型关闭按钮统一使用 `CloseIcon` SVG，
  禁止继续使用会受字体基线影响的原生 `×` 字形。
- 图标型关闭按钮必须明确设置双向居中、零内边距和零行高；SVG 必须固定宽高并使用块级显示。
- 本机真实页面必须量化按钮中心与 SVG 中心，X/Y 偏差均为 `0px` 才可通过。
- 本补充仅改变关闭控件视觉布局，不修改 API、数据库、权限、流程状态或业务数据。

## 2026-08-05 产品收敛补充：分工配置表信息降噪

- `/admin/assignments` 表格只显示步骤、工序、主责部门、当前负责人、协同人员、评审人员、
  匹配状态、分配来源和编辑操作等主要业务值。
- 删除节点编码、字段类型、内联编辑提示、协同部门、匹配原因、分配说明、项目分工版本和字段
  说明等灰色辅助小字；表格内 `small` 元素数量必须为 `0`。
- 分配状态使用中文；`SUGGESTED` 显示为“建议匹配”，不得在正式页面暴露英文枚举值。
- 项目切换和受控编辑面板必须继续可用；本补充不修改服务端分配逻辑、权限、数据库或业务数据。
