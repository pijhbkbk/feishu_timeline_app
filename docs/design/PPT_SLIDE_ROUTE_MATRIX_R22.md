## 2. 目标信息架构

### 2.1 五个一级入口

| 顺序 | 导航文案 | 路由 | 核心问题 | 唯一主动作 |
| --- | --- | --- | --- | --- |
| 1 | 工作台 | `/dashboard` | 我现在最应该推进什么？ | 提交当前任务进展 |
| 2 | 项目管理 | `/projects` | 哪些项目正常、阻塞或即将逾期？ | 进入项目工作区 |
| 3 | 我的任务 | `/tasks` | 我的待办按状态和紧迫度如何分布？ | 处理选中任务 |
| 4 | 进展提交 | `/progress` | 如何用最少步骤提交真实进展？ | 提交进展 |
| 5 | 复盘分析 | `/retrospectives` | 项目结束后发生了什么、为什么、下一次如何改进？ | 打开项目复盘 |

### 2.2 辅助入口

- 全局搜索、通知、帮助和个人中心进入顶栏工具区，不与五个业务入口争夺层级。
- 管理后台仅对有权限的管理员显示，并对直接访问 `/admin/**` 做前后端双重权限校验。
- 项目编辑、月度评审、材料库、日志等保留为项目工作区的上下文能力，不作为全局一级导航。
- 390px 视口使用折叠菜单或移动端底部导航；不得把现有宽侧栏直接堆到内容顶部。

| `/dashboard` | 重构 | `/dashboard` | 路由正确，但页面过长、指标过多，缺少个人问候与唯一当前任务 |
| `/projects` | 重构 | `/projects` | 保留搜索/筛选能力，默认视图从 10 列表格变为项目状态卡 |

## 5. 接口与模型映射

### 5.1 可直接复用或扩展

| 能力 | 当前接口/数据 | R22 处理 |
| --- | --- | --- |
| 流程图 | `GET /projects/:id/flow-map` | 保留后端流程裁决，只补充工作区所需摘要字段 |
| 当前任务详情 | `GET /workflows/tasks/:taskId/detail` | 复用工作内容、材料、附件、评审、日志、计划和动作集合 |
| 流程动作 | start/submit/approve/reject/return/complete | 保持后端权限、状态和幂等校验；前端只提交动作 |
| 任务表单草稿 | `PUT /workflows/tasks/:taskId/form` | 继续用于节点表单草稿，不冒充可追溯的进展历史 |
| 项目列表 | `GET /projects` | 扩展停滞原因、停滞天数、当前责任人、预计解阻时间 |
| 附件 | 现有对象存储凭证、校验、元数据绑定 | 保留 R19 扩展名、MIME、文件魔数、路径和权限防护 |
| 审计日志 | Prisma `ActivityLog` 与相关接口 | 继续不可覆盖，覆盖项目、流程、评审、附件和新增进展动作 |

### 5.2 Gate 1 之后需要新增或明确的数据契约

| 建议契约 | 用途 | 关键约束 |
| --- | --- | --- |
| `GET /dashboard/personal-overview` | 问候、当前任务、下一任务、个人统计、最近动态 | 按当前用户和数据范围聚合，局部数据失败可降级 |
| `GET /projects/board` | 项目卡与快速筛选 | 返回真实阻塞事实，不能只返回抽象“高风险” |
| `GET /projects/:id/workspace` | 项目头部、流程图、当前工序与摘要 | 流程状态来自后端，不由页面拼接 |
| `POST /tasks/:taskId/progress` | 三步面板提交进展 | 幂等键、权限校验、状态校验、审计日志；每次提交新增记录，不覆盖历史 |
| `GET /tasks?view=...` | 我的任务五类视图 | 支持待处理、评审中、即将到期、逾期、已完成及材料/风险摘要 |
| 任务—材料要求关系 | 自动填充上传上下文 | 附件仍只存对象存储，数据库只存元数据和业务关联 |
| 复盘模型与接口 | 生命周期指标、问题、结论、行动项和导出 | Prisma schema 与 migration 同步；结论有作者和版本历史 |
| `GET /admin/overview` | 用户、项目、待处理配置和系统健康摘要 | 管理员权限与数据范围校验不可只依赖导航隐藏 |

## 6. 路由兼容策略

- 对已有书签和测试可能使用的 `/tasks/my`、`/tasks/pending`、`/tasks/overdue`、`/projects/:id/flow-map` 先做显式重定向，不直接删除。
- `/projects/:id/overview` 保留真实编辑能力；`/projects/:id` 改为工作区后，所有进入项目的主链接统一指向根路由。
- `/progress` 和 `/materials/upload` 必须通过 `taskId` 恢复上下文；缺少或无权访问任务时展示明确错误/选择状态，不能无限加载。
- 角色不允许的 `/admin/**` 返回 403/无权限页；不能只隐藏菜单或依赖后端接口失败。

## 7. Gate 0 决策与待确认项

### 已形成的实现决策

1. PPT 是唯一视觉源头，但 PPT 内的 `PAGE DESIGN`、`DESIGN SYSTEM`、`INFORMATION ARCHITECTURE`、页码和解释文字仅作注释，不进入网页内容。
2. 项目根路由成为流程图与当前工序二栏工作区；成熟流程图内核复用，不重建通用 BPM 引擎。
3. 进展记录独立建模，不能用覆盖式任务表单草稿替代；真正的流程流转继续由后端控制。
4. 任务上传页复用既有安全上传链路，不降低 R19 的扩展名、MIME、文件魔数、路径穿越和权限校验。
5. 旧路由先重定向/降级，待端到端证据通过后再决定是否删除，避免破坏现有主链路。

### 需要在设计闸门确认的产品选择

1. 是否确认 `/retrospectives` 作为第五个一级入口文案“复盘分析”的汇总路由。
2. 是否确认 `/progress?taskId=...` 为可分享/可恢复的三步提交地址，而材料上传使用 `/materials/upload?taskId=...`。
3. 是否接受“项目资料编辑”从项目根路由降为工作区内次级入口。
4. 生产环境现有 R21C 演示 seed 在发布前必须清理或转换为明确测试租户；Gate 0 不改生产数据。
