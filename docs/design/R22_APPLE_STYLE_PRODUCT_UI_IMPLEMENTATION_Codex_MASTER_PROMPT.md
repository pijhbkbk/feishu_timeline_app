# R22｜Apple-like 产品 UI 全量还原与生产落地——Codex 主执行提示词

> **任务性质：** 产品级 UI 重构，不是局部美化，不是换色，不是静态原型。
>
> **最终目标：** 以《轻卡定制色开发系统_Apple风产品UI设计稿.pptx》为唯一视觉基准，将当前轻卡定制颜色开发项目管理系统重构为信息节制、层级清晰、操作顺畅、真实数据驱动的生产级 Web 应用。
>
> **执行原则：** 先解析设计，再实现；先本地和预发布验收，再生产部署；没有线上截图和真实交互证据，不得宣布完成。

## 0. 你的角色与任务

你是本项目的 **高级产品设计工程师、前端架构师和质量负责人**。你必须同时从以下三个角度完成任务：

1. **产品经理：** 保证每个页面只解决一个核心问题，用户最短路径清晰。
2. **高级 UI 工程师：** 高度还原 PPT 中的字号、层级、留白、卡片、颜色和交互。
3. **交付负责人：** 使用真实 API、完整测试、真实浏览器截图和线上验证证明功能已完成。

你不能只写组件、只新增路由、只通过构建，或者只声明“已部署”。最终用户必须能在生产站点真实看到与 PPT 设计一致的界面。

## 2. PPT 是视觉源头，但必须正确解释

PPT 共 12 页，含封面、设计规范、信息架构、页面设计和验收标准。

### 2.1 不得逐字照搬到网页的内容

以下内容属于设计稿注释，不是生产页面内容：

```text
PAGE DESIGN
DESIGN SYSTEM
INFORMATION ARCHITECTURE
KEY INTERACTION
NEXT
01｜员工工作台
02｜项目管理看板
```

这些文字只用于帮助理解设计，不应原样出现在生产网页中。

### 2.2 必须还原的内容

必须高度还原：

- 页面信息层级；
- 大标题、模块标题、正文和辅助文案的字号关系；
- 卡片比例与留白；
- 低饱和但有明确对比的色彩；
- 每个页面唯一的主动作；
- 员工、项目经理和管理层的最短操作路径；
- 页面中的核心字段和交互；
- 真实流程节点、任务、材料、风险和复盘信息。

### 2.3 不允许“像 PPT”却不能使用

最终结果必须是响应式、真实数据驱动、可操作的 Web 页面，不能：

- 把 PPT 截图作为背景；
- 把设计稿导出为一张大图片；
- 使用硬编码假项目冒充真实数据；
- 只实现静态卡片而没有点击行为；
- 只实现桌面截图，移动端不可用；
- 为了塞入所有信息而缩小字体。

# 第二阶段：建立全局设计系统

## 6. 字体：使用系统 Apple 风格字体栈，不打包字体文件

不得下载、提交或内嵌 Apple 字体文件。

使用：

```css
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "SF Pro Display",
  "SF Pro Text",
  "PingFang SC",
  "Microsoft YaHei",
  "Helvetica Neue",
  Arial,
  sans-serif;
```

中文在 macOS 优先使用苹方，在 Windows 优先使用微软雅黑，保证跨平台可读性。

### 6.1 字体层级

必须建立 token：

```css
--font-display: 40px;
--font-page-title: 32px;
--font-section-title: 26px;
--font-card-title: 18px;
--font-body: 16px;
--font-secondary: 14px;
--font-caption: 12px;
```

要求：

- 页面主标题：36–40px，字重 650–700；
- 页面说明：18–20px，行高 1.5；
- 模块标题：24–28px，字重 600；
- 卡片标题：17–19px，字重 600；
- 正文：16px，行高 1.6；
- 辅助说明：14px；
- 12px 只用于极少量标签、时间和角标；
- 表格和任务主要正文不得小于 15–16px；
- 不允许为了塞内容把主要文字缩到 12–13px。

### 6.2 页面留白

使用 8px 基础栅格：

```text
8px   极小间距
16px  组件内部间距
24px  卡片内边距
32px  模块间距
48px  大区块间距
64px  页面章节间距
```

页面容器：

```text
最大宽度：1440px
桌面横向内边距：48px
平板横向内边距：32px
手机横向内边距：20px
```

### 6.3 颜色系统

中性色：

```text
页面背景        #F5F5F7
卡片背景        #FFFFFF
一级文字        #1D1D1F
二级文字        #5E6470
弱化文字        #868E9C
边框            #E2E5E9
悬停背景        #F0F3F6
```

品牌色：

```text
主品牌蓝        #315F86
按钮悬停        #274D6D
浅蓝背景        #EAF1F7
焦点边框        #6E94B3
```

状态色：

```text
已完成          #367A54
进行中          #3D6F9D
待评审          #B27A21
已逾期          #B94C4C
已退回          #77589C
月度跟踪        #2F7B79
待退出          #93663D
未开始          #A3AAB4
```

禁止：

- 所有页面只有灰白而没有重点色；
- 每张卡片使用不同彩色背景；
- 整块卡片因为逾期全部变红；
- 低对比度灰色文字；
- 仅通过颜色表达状态，必须同时有文字或图标。

### 6.4 卡片

```text
圆角：20px
边框：1px solid #E2E5E9
阴影：0 8px 30px rgba(30, 44, 58, 0.06)
卡片内边距：24–28px
```

卡片层级主要依靠留白、标题和对齐，不依靠厚重边框或多层阴影。

### 6.5 按钮

主按钮：

```text
高度：48px
左右内边距：24px
圆角：12px
字号：16px
字重：600
背景：#315F86
文字：白色
```

次按钮：白底、细边框。

危险按钮只用于：退回、删除、终止项目。

点击区域不得小于 44×44px。

### 6.6 动效

```text
按钮反馈       120–160ms
卡片悬停       180ms
抽屉打开       220–260ms
状态更新       300ms
流程节点变化   400ms 以内
```

禁止持续闪烁、夸张弹跳和多个区域同时动画。

### 11.1 打开入口

从以下位置均可打开：

- 工作台当前任务；
- 项目工作区当前工序；
- 我的任务；

```text

```

或：


### 11.2 三步结构

#### 第一步：本次做了什么

状态选择：

```text

正在进行
已完成
遇到阻塞
```

字段：

```text

下一步计划
```

#### 第二步：是否有阻塞

仅选择“遇到阻塞”时展开：

```text

阻塞说明
需要谁协助
预计解除时间
```

阻塞类型：

```text

等待确认
供应商问题
人员问题
其他
```

#### 第三步：上传证明材料

显示必交材料 `n / total`，已提交、缺失和上传区。

底部固定：

```text
保存草稿｜提交进展
```

### 11.3 提交成功反馈

不能只显示“提交成功”，必须告诉用户：

- 哪个工序状态已更新；
- 系统自动创建了哪些下一步；
- 下一项分配给自己的任务是什么；
- 可返回工作台或进入下一任务。

### 11.4 提交进展与完成工序的区别

- 提交进展可以多次；
- 完成工序必须满足必填信息、必交材料、权限和前置条件；
- 如果不能完成，明确列出缺失条件，不得只禁用按钮。

## 17. API 策略

优先复用现有 API。

只有现有页面需要大量零散请求、导致加载割裂时，才新增聚合 API。建议但不强制：

```text
GET /api/dashboard/personal-overview
GET /api/projects/board
GET /api/projects/:projectId/workspace
GET /api/tasks/my
POST /api/tasks/:taskId/progress
GET /api/projects/:projectId/retrospective
GET /api/admin/overview
```

要求：

- 后端负责权限和业务判断；
- 前端不推导关键流程状态；
- 同一字段只有一个来源；
- 所有写操作有审计日志；
- 聚合 API 不得绕过项目权限。
